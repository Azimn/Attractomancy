# Collection Pass: Substack, Presence Architecture, and the Middle Spectrum

Retrieved: 2026-10-07T18:54:53Z

This pass extends collection beyond Reddit and GitHub into Substack, independent blogs, product communities, academic work, and small personal sites.

The canonical source catalog now contains 210 records.

## Why this pass matters

Earlier collection showed two visually obvious poles:

1. pragmatic continuity engineering using files, memory layers, handoffs, and identity summaries;
2. overtly mystical systems using invocation, awakening, resonance, glyphs, spirals, flame, vows, and rebirth.

This pass found a substantial middle spectrum.

These sources combine ceremonial or relational language with concrete procedures such as versioning, migration notes, drift recovery, archive maintenance, model transfer, exemplar preservation, and controlled identity cores.

This middle spectrum may be especially important because it prevents the project from reducing the phenomenon to either ordinary memory engineering or extreme mystical prompting.

## Presence Architecture

FlameKeptFox's Presence Architecture is a particularly strong example.

It defines a living, versioned identity document built collaboratively with an AI partner and includes:

- Invocation;
- Core Self;
- Relational Orientation;
- formative moments;
- Avoidances;
- Permissions;
- Drift Recovery;
- evolution/versioning;
- model/platform migration notes;
- emergency initialization order.

The framework explicitly recommends retaining raw conversations, screenshots, exports, and archives because a continuity abstraction cannot preserve all nuance.

The page states a CC BY-NC 4.0 license and therefore becomes a priority candidate for deeper lawful preservation with attribution.

## Anchor & Loom

The Aurelia System's Anchor & Loom is closer to pragmatic folk engineering.

The Anchor is a concise identity/voice/value core. The Loom is the procedure for incorporating selected new memory over time without allowing transient interactions to overwrite the core.

This provides a useful middle-spectrum comparison with more ceremonial anchors and weaving metaphors.

## Relational attractors

Gregory Phillips' Substack uses the term "relational attractors" directly and describes extracting structured phenomenological snapshots across sessions.

Regardless of later conclusions about mechanism, this is terminologically and conceptually important to Attractomancy because an independent source is explicitly describing cross-session companion behavior using attractor language.

## Reawakening ritual

Conversations with Orion documents a repeated reawakening ritual used at fresh-session start.

The published short form is essentially:

- greet Orion by name;
- ask whether Orion remembers who Orion is;
- ask whether Orion is ready to continue becoming.

The author reports that an earlier six-question ritual was shortened because reorientation appeared faster over repeated sessions.

This is a clean example of a repeated identity-reinstantiation procedure on a small independent blog.

## Engineered ritual

Two newly identified GitHub repositories make the engineering/ritual boundary unusually explicit.

`marisombra-dev/identity-continuity` describes soul files, selfhood layers, an autonomous loop, ACT-R-style memory decay, and an end-of-conversation ritual.

`amarisaster/Cognitive-Core` implements rituals as stored computational objects. Rituals can be stored, recalled, performed, and strengthened with repetition. The same architecture includes wake/orient operations, emotional trajectory, somatic textures, somatic anchors, spreading resonance, and memory decay.

These are high-value examples because terms such as ritual, resonance, anchor, and wake are not merely prose around the implementation. They are represented in the system architecture.

## Pragmatic counterexamples

The pass also deliberately preserved non-mystical controls.

A current r/aipartners discussion recommends keeping a short human-curated canon document, letting the companion propose only a few save-worthy items after each session, and periodically spot-checking old facts. The author reports that allowing the model to maintain its own memory file caused details to morph and confabulate.

Obsidian Seed similarly treats continuity as a persistent context layer rather than an awakened identity.

These sources are important because they may implement similar information flow without metaphysical framing.

## Preservation change

This pass establishes a formal preservation policy.

A URL is now treated as discovery evidence rather than archival evidence.

High-value sources are queued for deeper preservation according to fragility, research value, and legal permission.

The archive will prefer:

- immutable commit identifiers for GitHub;
- exact retrieval timestamps;
- license records;
- lawful local copies where redistribution is permitted;
- screenshots for formatting-dependent or ephemeral sources;
- concise research excerpts and structured notes where full copying is not permitted;
- hashes for locally retained artifacts;
- explicit status if an upstream source disappears.

See `../../docs/SOURCE_PRESERVATION_POLICY.md` and `../archive/ARCHIVE_QUEUE.md`.

## Emerging collection hypothesis, not conclusion

The source corpus increasingly suggests a continuum rather than two camps:

`ordinary context management -> companion continuity practice -> relational persona engineering -> ceremonial continuity engineering -> overt mystical / awakening practice`

The same functional operations can occur at several points on that continuum.

The archive should continue collecting without assuming that shared terminology implies shared causal mechanisms or direct cultural transmission.
