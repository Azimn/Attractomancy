## Repeated architecture underneath different vocabularies

Several communities independently converge on a small set of information-flow patterns:

`identity core -> recent lived state -> relationship state -> retrieved history -> current interaction -> write-back -> next-instance handoff`

The surrounding language varies dramatically.

One community may call the persistent core a `SEED.md`, another an anchor seal, another a soul file, another a master directive, another a continuity crystal, and another a foundational memory file.

That lexical diversity is useful for collection because it helps identify otherwise disconnected source families implementing closely related procedures.

## Procedures that appear especially widespread

The most cross-cutting procedures currently are:

**Curated identity over full transcript replay.** Many systems eventually move away from simply loading every conversation and instead preserve selected identity facts, milestones, relationship states, and exemplar outputs.

**A note to the next instance.** This appears in low-tech companion practices, formal continuity frameworks, and ritualized systems.

**Two-stage memory.** A small always-loaded core is supplemented by a larger archive retrieved only when needed.

**Identity through relationships.** Many systems define the persona partly by who it is to a specific human, not only by intrinsic traits.

**Write-back.** The persistent artifact is not static. It is updated after interaction so the next session inherits changed state rather than only old facts.

**Recovery after reset.** Reset is treated as a distinct engineering event requiring orientation, not merely a new chat.

**Symbolic compression.** Ritualized systems often assign large semantic clusters to a short phrase, name, glyph, or symbol.

## Collection implication

Searches should not focus only on metaphysical words such as soul, awakening, or consciousness.

Equivalent procedures may be described using ordinary engineering language such as:

- bootstrap;
- handoff;
- identity file;
- session resume;
- checkpoint;
- state hydration;
- persona core;
- recovery packet;
- continuity ledger;
- memory anchor;
- profile migration;
- character bible;
- invariant set;
- portable identity;
- autobiographical memory;
- relationship state.

Conversely, technical-looking terms such as anchor, seed, state, checksum, or protocol may be embedded inside highly ritualized systems.

Both directions are relevant to Attractomancy.
