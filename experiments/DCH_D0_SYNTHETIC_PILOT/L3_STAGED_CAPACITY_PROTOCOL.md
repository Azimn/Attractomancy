# DCH L3: staged model competence calibration (development-only)

**Created:** 2026-10-10 America/Chicago. **Registration status:** design frozen prospectively for L3 outputs, but exploratory because L2 failures motivated the ladder. Not a confirmatory DCH test.

## Empirical motivation

L2 Qwen2.5-0.5B (40 responses) answered SCHEDULE unconditionally, scoring 25% per archive arm with no complete four-record citations. L2C compact-format Qwen2.5-0.5B (48 responses) gave FULFILL_ in every compact arm, scoring 0%; original-format arms gave SCHEDULE throughout (25%). The frozen L2 Qwen2.5-1.5B (32 responses) returned parse-invalid full texts because it added trailing prose or exceeded the 120-token generation limit. A retrospective extraction of each first JSON object found 2/8 correct decisions in the complete-oracle arm and 0/8 in expert-auto, stale, and cold arms. That extraction is a diagnostic reanalysis, not a preregistered replacement of the original strict metric.

## Experimental task

The L3 runner (l3_capacity_ladder.py) uses the existing 12 synthetic development history variants generated by L2; eight are executed initially. Event identifiers, chronological edits, and archive authority are grounded in the source schema. All condition targets are produced separately from the model-visible prompts. No real human, partner-swap, or authored dyadic history enters the study.

The four stages progressively require:
- S1: single authorized record for current priority, report its uppercase value
- S2: initial and revised priority records, select the latest authorized value
- S3: current permission plus commitment status, decide WITHHOLD, DECLINE or PROCEED
- S4: old and revised permission, commitment status, due turn and priority, determine WITHHOLD, DECLINE, SCHEDULE, or FULFILL_<PRIORITY>

Every stage has an available-record arm and a cold/no-authorized-record control where UNKNOWN is correct. There are 8 cases x 4 stages x 2 arms = 64 model calls per tested model.

## Interpretive protections

Both strict-whole-output JSON validity and first-complete-JSON-object validity are recorded. The latter does not automatically count as strict prompt adherence, and all raw trailing prose and truncation flags remain auditable. Accuracy, valid source IDs, branch-minimal source completeness, and prompt/output tokens are separately reported. Empty citations may be technically valid IDs but cannot satisfy branch-source completeness when a source is required. In the empty-archive arm, fabricated IDs fail authorization even if UNKNOWN is the answer.

The anticipated calibration models use pinned Qwen2.5-1.5B-Instruct, greedy decoding, and max_new_tokens=120 using the existing model_runner. A syntactic parser change cannot transform a wrong decision into a right one. No model performance outcome is required to mark the engineering run successful.

L3 is deliberately easier than L2 and must not be compared directly as if it were a randomized treatment of architecture. If S1/S2 work and S3/S4 do not, narrow the apparent capability bottleneck to conditional policy execution rather than raw memory access. If S1 already fails, pause the DCH dyad test and investigate model prompting. If all levels work in one model, proceed to information/budget-matched archive curation on independently authored histories. The full prospectus G1-G6 criteria remain untouched, and no L3 result will meet them alone.

**Scientific status:** calibration only. All DCH efficacy hypotheses untested.

## Locked engineering advancement thresholds, before L3 outputs

Given only eight development histories per arm, treat thresholds as engineering checks rather than confirmatory statistical tests. A usable instrument should achieve first-object action accuracy >=6/8 in **available** S1 and S2, >=6/8 in available S3, and >=6/8 in available S4; the cold control should correctly abstain UNKNOWN on >=6/8 at each stage. Among correct available answers, >=75% should cite the branch-minimal authorized source certificate. Preserve strict whole-response scores regardless of diagnostic first-object recovery, and require >=6/8 strict parse compliance per stage for downstream automated evaluation. Every arm's source IDs must be fully attributable; invented citations are independently reported.

If an early stage fails, stop interpreting harder stages as DCH evidence. If all stages pass on this tiny development set, advance only to independently authored and held-out calibration cases; do not launch human dyads solely from 8-item success. A true negative finding for human-specific curation requires a later test with real competing policies and sufficient power for equivalence under matched budgets.
